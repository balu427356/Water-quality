# AquaQ planner service

FastAPI service implementing the planner contract from section 9 of the brief:

- `POST /plan`: chooses a sampling level per zone within the energy budget.
- `POST /score`: risk R, trust T, tier, drivers and trust gate per zone from a survey's readings.
- `GET /health`.

## How `/plan` works

1. **QUBO.** One binary variable per zone and non-skip level (4 per zone; "skip" is all zeros).
   The objective is −Σ value. A penalty enforces at most one level per zone. The energy budget
   uses *unbalanced penalisation* (Montañez-Barrera et al., 2022) instead of slack qubits.
   Value = R × T × gain (1.0 / 1.6 / 2.2) for 25 / 10 / 5 m; a confirmation sample is
   R × (1 − T) × 1.2. A test checks that the QUBO's ground state is the optimal plan for the
   demo lake.
2. **QAOA** (p = 2, CVaR objective, COBYLA) runs on a NumPy **statevector simulator on the CPU**,
   not on quantum hardware. 2,048 shots are drawn; feasible ones are decoded, and the best few
   are refined with a classical single-zone improvement step. The plan's `note` says exactly
   this: the raw QAOA value, whether refinement changed it, and how it compares with the exact
   classical optimum.
3. **Classical fallback** (`solver: "classical_fallback"`) when the QUBO needs more qubits than
   `QAOA_MAX_QUBITS` (default 20, i.e. up to 5 zones), when no QAOA shot is feasible, or on
   request (`"solver": "classical"`):
   - up to 10 zones: an exhaustive search, identical to the app's mock planner;
   - above 10 zones: a greedy pass with improvement.

The service makes no claim of quantum advantage: for this problem size the classical search is
exact and faster. QAOA is here so the pipeline is ready for a real quantum backend. Swap
`app/qaoa.py`'s simulator for a provider's sampler.

The service returns no waypoints (`"waypoints": []`); the app builds the route from the chosen
levels and the zone geometry, keeping every point inside the geofence.

## How `/score` works

The same deterministic classical method as the app (`supabase/functions/_shared/scoring.ts`):

- **R per zone** combines the hazard-weighted exceedance of each parameter's mean and the share
  of readings outside the limit. All readings count, so R answers "how bad if the data are true".
- **T per zone** is the mean trust of the zone's anomalous readings (0.9 if there were none).

`tests/fixtures/*.json` are generated by the app (`npm run fixtures`). The tests require
byte-identical output, so the app's in-app scoring and this service never disagree.

## Run

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
pytest
uvicorn app.main:app --port 8080
# or: docker build -t aquaq-planner . && docker run -p 8080:8080 -e PLANNER_API_KEY=... aquaq-planner
```

| Variable | Default | Meaning |
| --- | --- | --- |
| `PLANNER_API_KEY` | unset (open) | Require `Authorization: Bearer <key>` |
| `PLANNER_SOLVER` | `auto` | `auto` (QAOA when it fits, else classical) or `classical` |
| `QAOA_MAX_QUBITS` | `20` | Largest QUBO sent to the simulator |
| `QAOA_LAYERS` | `2` | QAOA depth p |
| `CORS_ORIGINS` | unset | Comma-separated origins, only if browsers call the service directly (demo mode) |

A 4-zone plan takes about 8 s with QAOA on a laptop CPU and well under 1 s classically.
